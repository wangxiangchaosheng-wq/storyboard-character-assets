# 透明输出工作流

第一次图片生成前读取本文件。目标是得到文件层面的真实 Alpha，不是视觉上像透明的棋盘格。

## 路径 A：原生 Alpha（优先）

1. 按 `$imagegen` 使用内置图片工具，请求真实透明背景和 PNG。
2. 先生成阵容中最核心的一张校准样片并保存到项目。
3. 运行 `scripts/validate_character_assets.py`。
4. 只有文件包含 alpha、透明像素比例合理且视觉检查通过，才继续整组生成。

如果输出为 RGB、棋盘格被绘制进背景或没有透明像素，路径 A 失败。不要反复用“移除棋盘格”编辑同一张图；改走路径 B。

## 路径 B：纯色底转 Alpha（自动回退）

重新生成校准人物，要求背景为均匀、无纹理的高色度纯色。默认使用 `#FF00FF`，因为常见历史、商务和生活题材很少需要纯品红主体。

提示词必须明确：

- 背景覆盖整张画布，只有一种颜色。
- 无渐变、纹理、网格、地面、阴影、环境或光晕。
- 人物轮廓完整，顶部和左右至少约 8% 纯色安全边距；默认半身像的衣袍必须在画布底边形成宽幅连续的平直截断，不得留下透明缝，也不得为了四边留白做成圆弧或悬浮收口。
- 人物、服装、道具和特效不得使用抠图色。
- 不再提“透明背景”或“棋盘格”。

保存草稿后运行：

```bash
python3 scripts/chroma_to_alpha.py draft.png final.png \
  --key '#FF00FF' --mode all --allow-bottom-touch --preview-dir qa
python3 scripts/align_bottom_crop.py final.png aligned.png
python3 scripts/validate_character_assets.py --require-bottom-touch aligned.png
```

转换器默认使用 `tolerance 200`、`feather 300`、`feather-radius 5px`。这些参数针对“主体完全禁用幕布色”的任务生成草稿，并把羽化限制在紧邻轮廓的小范围内，避免整个人物变成半透明。只有黑白底预览证明主体颜色和细节未受损时才可沿用；否则优先更换幕布色或重新生成草稿，不靠盲目放宽参数补救。

`--mode all` 适合专门生成、主体明确禁用抠图色的纯色底草稿，也能清除手臂与身体之间的封闭背景区域。`--mode connected` 只移除与画布边缘连通的背景，适合恢复来源不完全确定的草稿，但可能保留封闭孔洞。

如果主体必须使用品红，先根据 style bible 选择纯青 `#00FFFF` 或纯绿 `#00FF00`，并在全组提示词和脚本参数中保持一致。不要每个人物使用不同抠图色。

## 校准与批量

路径 B 的校准图必须同时通过：

- 转换脚本的输入覆盖率与输出占用率检查。
- `validate_character_assets.py` 的 PNG、尺寸和 Alpha 检查。
- `--require-bottom-touch` 的宽幅底边接触检查；若只差透明缝且下缘已平直，可先用 `align_bottom_crop.py` 向下对齐。
- 黑底、白底视觉预览的边缘检查。
- `view_image` 对身份、服饰、姿态、构图和水印的检查。

校准通过后，整组固定使用同一纯色、容差、取景比例和转换命令。每张草稿单独转换并校验，不要把多个人物拼进一张图再抠。

## 停止条件

纯色底校准失败时，只允许一次定向重生成，重点修正背景均匀度、主体与抠图色色差、顶部/左右留白或底部裁切形态。第二次仍失败就停止，保留草稿与校验输出并说明原因；不要擅自切换 CLI/API、模型或把不合格图片标记为最终资产。

## 内部 QA 与最终输出隔离

透明路径、key、mode、tolerance、feather、feather-radius、Alpha 指标和黑白底预览只作为内部工作状态，不默认生成 `manifest.md` 或向用户展示。

草稿与黑白底预览放在任务专用临时目录或非交付工作目录。最终主题交付目录只保留 5 张通过验收的 RGBA PNG；默认最终回复也只展示这 5 张图片。只有用户明确要求 QA 证据或生成记录时，才额外提供。
