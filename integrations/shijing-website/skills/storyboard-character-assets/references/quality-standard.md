# 人物资产质量标准

多角色资产批量交付、透明边缘要求较高或需要接入页面时读取本文件。

## 单张视觉检查

按以下顺序检查，避免先被细节吸引而漏掉硬错误：

1. **取景 / 原子性 / 文件与数量**：文件可打开；默认是**腰部以上半身像**，完整头冠/头发、肩臂、双手和唯一人物道具，腰/胯上缘以下衣袍必须由画布底边形成宽幅连续的平直截断且不留透明缝；画面中**恰好 1 个目标人物 + 1 个主动作 + 1 个人物道具**；0 件或 2 件以上人物道具、圆弧/椭圆/徽章/悬浮收口、膝盖、脚、蹲跪、全身、第二人物、群众、幽灵肢体、重复脸、同人多姿态、character sheet、sticker sheet、collage、分镜或海报式组合均直接 FAIL。
2. **身份、设定与唯一道具史实**：身份锚点清楚；时代、职业、阵营、服装和道具没有明显错置。唯一核心道具已经按 Prop Card 画出，且人物确实在使用、佩用或查看。核对该道具的 `PERSON-ATTESTED / PERIOD-ATTESTED / LATER-TEXT-ATTESTED` 等级、直接来源、图中形制与允许声称范围；道具漏画、模型擅自新增第二件道具、只有影视/绘画惯例、来源缺失、时代不符或拼装出的伪器物均直接 FAIL。**不得把身份或抽象能力直接翻译成未经研究的道具**（如军师=地图、现代思维=古代数据板），也不得以严谨为由让人物空手。
3. **叙事动作 / Action Signature**：动作必须对应具体事件瞬间与角色功能；至少能看出一个明确主动动词。重心可信，手部与道具形成因果关系，视线有对象。若把人物名字换成同组另一人后仍完全成立，判为动作特异性不足。生成前的内部动作评分必须 ≥8/10。
4. **构图与裁切**：采用系列统一的腰部以上半身取景；帽冠、发饰、双手、衣袖和动作道具没有意外被裁断。腰/胯上缘以下衣袍必须在画布底边形成宽幅连续的平直截断且不留透明缝；不做圆弧、椭圆、徽章、悬浮或渐隐式底部。
5. **透明边缘**：背景确实透明；轮廓无白边、黑边、彩边、脏像素或半透明背景残留。
6. **干净交付**：无文字、水印、签名、边框、底座、场景或不需要的投影；唯一人物道具保持局部从属，不得扩张成完整环境。

## 整组一致性检查

把人物并排查看，重点比较：

- 头身比例、镜头高度与画布占用率
- 贴底平直裁切高度是否一致；是否有人变成圆弧/悬浮底部、四分之三身、全身、蹲姿或跪姿
- 线条粗细、材质颗粒与细节密度
- 主光方向、阴影软硬与对比度
- 饱和度、黑白层级和公共配色逻辑
- 透明边缘的锐度和羽化程度
- 姿态是否有区分，同时仍像同一套资产
- 每个人的主动动词是否不同或具有不同执行方式
- 道具是否被真正使用，而不是所有人都“拿着一个东西”
- 每人是否恰好有 1 件经过研究的核心道具；是否有人漏画道具、增加第二件道具或把两件物品伪装成一套
- 每件可见道具是否都有证据等级和直接来源；是否出现无来源复合器物或把现代概念伪装成古代器械
- 是否存在题材驱动的核心道具同质化：例如三国角色全员地图、全员卷轴、全员持兵器；若同类核心道具重复，物理操作方式与叙事功能是否不可互换
- 地图专项：仅在动作必须依赖地理路线时出现；无大面积疆域、地名、箭头、信息图，且未把地图当成军师/将领默认识别物
- 角色剪影是否能在缩小到约 15–20% 尺寸时仍快速区分

一致不等于复制。应统一视觉语法，同时让轮廓、动作逻辑、道具交互和局部配色足以快速区分角色。

## 脚本检查

运行：

```bash
python3 scripts/validate_character_assets.py --require-bottom-touch <png> [<png> ...]
```

脚本的 `FAIL` 是必须处理的问题；`WARN` 需要结合画面判断：

- `FAIL`：不是 PNG、尺寸过小、没有 alpha、没有足够清晰透明像素、外边框或四角不透明、几乎为空或文件损坏。
- `WARN`：主体大量接触画布边缘，可能发生裁切；或格式超出脚本能精确分析的范围。

脚本不会判断史实、身份、服装、手部、画风或水印，因此不能替代 `view_image` 的视觉检查。

## 纯色幕布转 Alpha

只有为本次任务专门生成、背景明确约定为均匀高色度纯色的草稿，才能运行：

```bash
python3 scripts/chroma_to_alpha.py draft.png final.png \
  --key '#FF00FF' --mode all --allow-bottom-touch --preview-dir qa
python3 scripts/align_bottom_crop.py final.png aligned.png
python3 scripts/validate_character_assets.py --require-bottom-touch aligned.png
```

转换脚本必须先确认幕布覆盖足够多的画布边缘、被移除区域与保留主体比例合理；顶部和左右不得贴边，默认半身像的衣袍必须在底边形成宽幅连续接触。输出与输入必须使用不同路径，默认不覆盖既有文件。

黑底和白底预览只用于质检，不是最终资产。两种底色上都检查：

- 发丝、羽毛和布料边缘没有品红/青/绿残边；
- 浅色服装没有被误删或变成半透明；
- 手指、武器细杆、帽带和披风没有断裂；
- 顶部和左右存在透明安全边距；底部是平直、自然的有意半身裁切，没有圆弧/悬浮收口；
- 没有矩形雾层、地面阴影或残留色块。

不得对复杂场景、普通照片或未知背景使用该脚本。幕布不均匀或主体使用了幕布色时，应重新生成草稿，不得持续扩大容差掩盖问题。

## 修正优先级

1. 错人、**错误取景（圆弧/悬浮底部、全身/四分之三身/膝脚/蹲跪）、多人物/群像/拼贴/角色表/多个姿态**、无透明背景、严重裁切、幕布残边或损坏文件。取景或原子性失败必须从空白重新生成，不得拿错误图继续编辑或直接硬裁。
2. 任一可见道具缺少史料/器物依据、时代或形制错误、出现伪古董；Action Signature 没有落实、姿态不成立或角色动作过于通用。
3. 与整组不一致的取景、比例、光线或渲染风格。
4. 不影响使用的小瑕疵。

每轮只指定一个主要变化，并重复身份与 style bible 不变项。身份、姿态或画风错误时重新生成该角色；原生 Alpha 失败时优先走纯色幕布回退。不要用不断放宽抠图容差代替合格输入。

## 内部角色数量与原子性记录

未指定数量时，内部工作状态确认：默认核心角色数与最终 PNG 数均为 5；每张资产的原子性检查为 `1 character / 1 action / 1 prop / no collage / no scene / no text = PASS`。

Action Signature、Prop Card、史据链接、提示词、透明路径、Alpha 指标和黑白底预览结果只用于内部生成与验收。不要为默认任务创建 `manifest.md`，也不要在最终回复中展示这些记录。最终交付目录和最终回复都只包含 5 张通过验收的 RGBA PNG；只有用户明确索要时才输出过程记录。
