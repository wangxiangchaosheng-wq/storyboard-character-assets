# 透明 PNG 执行契约

本文件定义透明人物资产的执行边界。目标是得到文件层面的真实 Alpha，而不是“看起来像透明”的棋盘格、白底或纯色底。完整回退步骤见 [transparency-workflow.md](transparency-workflow.md)。

## 1. 先探测能力，不编造参数

每次执行都先查看当前图片工具实际暴露的参数结构：

- 工具明确提供透明背景、背景模式或输出格式字段时，按其真实字段设置。
- 工具没有提供这些字段时，不得假设它支持，也不得在调用中添加未暴露的 `transparent_background=true` 等参数。
- prompt 中的“真实透明背景、无场景”只能表达视觉意图，不能证明输出文件拥有 Alpha。
- PNG 扩展名本身不等于透明；必须落盘检查。

## 2. 内置图片工具路径

当前工具没有结构化透明参数时：

1. 仍可先按 `$imagegen` 请求单人物、无场景、真实透明 PNG，作为原生 Alpha 校准尝试。
2. 保存第一张校准样片并运行 `scripts/validate_character_assets.py`。
3. 若输出确有合格 Alpha，整组可继续使用原生 Alpha 路径。
4. 若输出为 RGB、画入棋盘格或保留不透明背景，不反复编辑失败图，直接进入纯色幕布回退。

不得把“模型声称透明”“界面预览像透明”或“文件名是 PNG”写成通过结论。

## 3. OpenAI Images API / CLI 路径

只有用户明确要求 API/CLI、运行环境已经提供可用凭据与路径，或当前任务已获相应授权时才使用。按照当时官方文档和实际 SDK 参数，选择支持透明输出的模型，并显式请求：

```python
client.images.generate(
    model=selected_supported_model,
    prompt=prompt,
    background="transparent",
    output_format="png",
    n=1,
)
```

编辑路径同样保留 `background="transparent"` 与 `output_format="png"`。必要时可附加当时受支持的尺寸和质量参数。若 SDK 或模型拒绝这些字段，停止该路径并报告真实错误；不得假装参数已生效。

官方文档：
https://developers.openai.com/api/docs/guides/image-generation

## 4. 纯色幕布回退的授权边界

调用本 skill 允许对本次专门生成的均匀高色度幕布草稿执行确定性的本地 Alpha 转换，但仅限以下条件：

- 草稿是本任务为抠图专门生成；
- 幕布颜色已知且覆盖画布边缘；
- 人物和唯一人物道具明确禁用了幕布色；
- 没有复杂场景、渐变、纹理、地面或未知来源背景。

不得把 `chroma_to_alpha.py` 用作任意用户照片或复杂背景的通用抠图工具。条件不满足时重新生成合格草稿，不通过扩大容差强行抠图。

## 5. 文件级通过条件

每张最终资产必须同时满足：

- 是可读取的 PNG；
- 存在 Alpha 通道或等价透明信息；
- 清晰透明像素比例达到校验门槛；
- 外边框大部分清晰透明，四角透明；默认半身像的衣袍必须在底边形成宽幅连续接触且不留透明缝；
- 可见主体不是空图；顶部和左右关键部位没有意外贴边，底部为平直自然的半身裁切而非圆弧/悬浮收口；
- 黑底和白底预览均无明显白边、黑边、彩边或半透明雾；
- 视觉上恰好一个人物、一个主动作，无场景、文字或第二人物。

## 6. 硬失败

以下任一情况均不得交付：

- 没有 Alpha；
- 棋盘格被直接画进图片；
- 四角或大面积背景不透明；
- 透明像素只占极小比例，仍像完整矩形背景；
- 人物周围有明显白边、黑边、幕布色残边或大面积半透明雾；
- 关键发丝、手指、兵器、帽带或衣摆被误删；
- 仅依据扩展名、prompt 或生成说明宣称“已抠图”。

透明流程的优先级是：真实工具能力 → 原生 Alpha 校准 → 文件校验 → 纯色幕布回退 → 黑白底视觉检查。缺少文件校验或视觉检查时，不得宣称完成。
