# 故事板人物资产

把主题转化为一组“选角有依据、动作有角色特异性、风格一致、真正可落地”的**半身单人物原子资产**。保留用户已经指定的人物、风格、数量、尺寸和交付位置；不要为了完整感擅自扩写主题或增加无关角色。**主题决定选谁，但每张图永远只允许一个人物、一个主动作；默认构图是腰部以上半身像，不是全身动作插画。**

## 默认执行契约

当本 skill 已被调用且用户只输入一个事件主题时，把该主题视为完整、可执行的生成请求。默认一次性完成：主题理解与必要研究 → 选择 5 个关键人物 → 共享美术规范 → 逐人生成透明 PNG → 视觉与文件质检 → 保存 5 张最终资产。**默认最终回复只展示这 5 张免抠 PNG，不附清单、说明、路径列表、提示词、史据、QA 图、压缩包或其他文件。**

- 不要停在问题分析、角色名单、提示词或“是否继续生成”的确认上；这些都是生成过程的中间步骤。
- 主题即使写成疑问句、假设句或论坛标题，也要先用简短推演确定叙事冲突和关键行动者，然后继续生成人物资产，而不是只回答问题。
- 缺少时间点、人物数量、画风或尺寸时，采用最保守且有依据的默认值，在内部工作记录中保留假设后继续；不为此生成面向用户的说明文件。只有不同选择会导致互不兼容的身份描绘，且没有合理默认值时才提问。
- 未指定阵容时，固定选择 **5 个最不可替代角色**，不要等待用户批准名单。只有用户明确要求其他数量时才改变最终 PNG 数量。未指定画风时，根据题材选择克制、易读的统一视觉方向；已有适用参考图时优先利用。
- 未指定取景时，固定使用**腰部以上半身像**：完整头部、肩臂、双手和唯一人物道具进入画面，腰/胯上缘以下的衣袍必须由画布底边做平直、自然的半身裁切，且在底边形成足够宽的连续接触。不得在主体与底边之间留下透明缝，不得把衣袍底部做成圆弧、椭圆、徽章式、悬浮式或渐隐式收口。不得为了表现动作自动改成全身、四分之三身、蹲姿、跪姿、行走或跨步；只有用户明确要求全身/坐姿/战斗动作，或交付版式确实必须显示下肢时，才允许改变。
- 只有用户明确说“先给方案”“不要生成图片”“只要提示词/选角”时，才停在文本交付阶段。

## 依赖与执行模式

- 任务包含图片生成或编辑时，第一次图片调用前先读取并遵循 `$imagegen`。默认可使用内置 `image_gen`；只有用户明确要求 CLI、API 或模型参数，或当前执行环境已经提供可用的 Images API 路径时，才进入 API/CLI 流程。
- **第一次图片调用前必须读取 [references/atomicity-contract.md](references/atomicity-contract.md)。一个资产只能包含一个人物和一个主动作和一个人物道具。**
- **凡是透明人物资产，第一次图片调用前必须读取 [references/transparency-contract.md](references/transparency-contract.md) 与 [references/transparency-workflow.md](references/transparency-workflow.md)。透明不能只靠 prompt，也不能假设工具拥有未暴露的参数。**
- 先检查当前图片工具的真实参数结构：只有工具明确暴露透明背景或输出格式字段时才设置；不得编造 `transparent_background=true` 等当前工具并不支持的字段。没有结构化透明参数时，先请求原生透明并以落盘 Alpha 为准，失败则自动走纯色幕布回退。
- 使用 OpenAI Images API/CLI 且其当前文档支持时，透明人物资产显式设置 `background="transparent"` 与 `output_format="png"`；PNG 扩展名本身不等于透明。
- 不要把内置图片工具宣称为某个具体模型。用户明确要求 `gpt-image-2` 时，按 `$imagegen` 与透明契约的 API/CLI 规则处理。
- 用户明确只要选角、资产规划或提示词时，交付相应文本，不要擅自生成图片；否则默认完成图片生成。
- 调用本 skill 即表示允许对**本次专门生成的均匀纯色幕布草稿**执行项目内、确定性的 Alpha 转换。该转换不得用于任意用户照片、复杂背景或来源不明的图片，也不得改变人物身份、服饰、姿态和画风。

## 工作流

### 1. 形成任务简报

从请求中提取：主题与时间范围、叙事目的、使用场景、受众、指定或排除的人物、资产数量、画风、画幅/尺寸、透明背景要求、参考图、交付目录，以及是否要接入现有页面。

只在缺失信息会实质改变人物身份且无法合理推断时提问；其余情况做保守且可逆的假设并明确写入简报，然后继续生成。**未指定数量时默认选择 5 个最不可替代角色。** 若主题确实少于 5 个有意义的独立行动者，不得虚构凑数；若第 6 个及以后角色会显著改变关键因果链、重大分歧或最终结论，可额外加入，但必须通过角色扩展门槛并记录理由。

### 2. 研究主题并确定阵容

历史事件、现实议题、真实人物或正在变化的主题，需要先核实身份、时间、阵营、作用和关键争议；优先权威或一手来源。虚构主题优先依据用户材料与正式设定。不要把推测、演义设定或视觉想象写成事实。

选角前按需读取 [references/character-selection.md](references/character-selection.md)。在内部形成“角色方案”，先按反事实不可替代性排序，**默认锁定前 5 名**；为每个人说明：为什么不可替代、在事件链中的功能、视觉识别点、事实置信度或设定依据。第 6 名及以后只有通过“扩展角色门槛”才允许加入。群体概念（如“1 万大学生”）默认只生成 1 个代表性人物资产，除非其内部子角色分别通过扩展门槛。

**然后必须依次读取 [references/atomicity-contract.md](references/atomicity-contract.md)、[references/historical-props.md](references/historical-props.md) 与 [references/action-signature.md](references/action-signature.md)。先锁死一个资产 = 一个人物 = 一个主动作 = 一个人物道具 = 一个腰部以上半身像；再为每个历史人物研究 2–3 个候选道具并完成 Prop Card，最终只选出 1 件有依据、能表达身份或当前行动的核心道具；最后让这 1 件道具与动作一起形成 Action Signature：具体事件瞬间 → 叙事功能 → 能力来源 → 主动动词 → 道具交互 → 上身朝向与肩线 → 视线 → 表情 → 半身剪影 → 禁止的通用摆拍。** 动作特异性评分低于 8/10 时不得进入图片生成。不要只写“适合的姿态”四个字，也不要把人物名简单映射成未经研究的识别道具。动作若必须依赖膝地、蹲伏、奔跑或完整下肢才能读懂，应重新设计成半身框内可读的手势、操作和视线关系。

道具规划必须同时执行**叙事适配、史实适配与组内去同质化检查**。不再以“手势勉强也能成立”为理由优先删道具。地图、军图、兵器、书卷、现代设备等仍不是身份自动触发物。若两名及以上角色使用同类核心道具，必须证明其动作机制和叙事功能不可互换；否则至少重设计其中一人的动作/道具。随后立即把角色方案、`Prop Card` 与 Action Signature 转化为逐人提示词；不要在这里等待确认。上述研究只用于内部生成与验收，不默认写成用户清单。用户已指定阵容时，以补充与纠错为主，不自行替换。

真实历史题材还必须通过**全道具史实门槛**：画面中唯一的人物道具（包括用户熟悉的标志性物件、兵器、文书、饰物和手中小物）必须至少有同一时代/相邻时代的文献或考古器物依据，并记录直接来源。人物专属使用关系分为 `PERSON-ATTESTED`（近同时代史料/实物直接关联）、`PERIOD-ATTESTED`（器物类型与形制符合时代，但不声称此人用过）、`LATER-TEXT-ATTESTED`（后世早期文献关联；仅当器物类型本身也符合时代时可用，并必须写明证据年代差）。只有后世影视/绘画惯例、没有史料或器物依据的道具不得入图。不得把多个真实器物概念拼成一个没有来源的“伪古董”，也不得为了把现代思维可视化而发明古代版流程板、数据面板、控制台或其他混合装置。无法确认某个候选时，应换用另一个有依据的候选；若候选仍不合格，继续研究或重新设计动作，在找到 1 件合格人物道具前不得进入图片生成。**每张资产必须恰好有 1 个人物道具，不能删光，也不能多画。**

### 3. 锁定共享美术规范

在生成第一张图前建立一份可复用的 style bible，至少锁定：

- 媒介与画风
- 时代/世界观准确度
- 轮廓复杂度与细节密度
- 统一取景、视角、人物比例和画布占用率
- 线条、材质、光线、色彩与阴影方式
- 透明背景、留白和裁切规则
- 全组共同的禁止项

用户提供的参考图要标明用途：身份参考、服饰参考、姿态参考或仅风格参考。不要从参考图推断未说明的身份信息。

本 skill 附带的两张三国人物图只适用于用户明确要求“中国历史手绘/工笔水彩式角色立绘”等相近方向时，作为**风格参考**使用；不要把它们设为所有主题的默认画风：

- [诸葛亮风格示例](assets/style-reference/three-kingdoms-zhuge-liang.png)
- [魏延风格示例](assets/style-reference/three-kingdoms-wei-yan.png)

编写图片提示词前读取 [references/prompt-template.md](references/prompt-template.md)。同一组资产必须逐字复用 style bible 的公共部分，只替换人物身份、服饰、道具、Action Signature 和表情等角色变量。**人物差异优先通过动作逻辑与轮廓建立，而不是仅通过换衣服、换道具或左右镜像。**

除非用户明确指定其他取景，style bible 必须把以下规则写成固定不变项：**waist-up half-body portrait / 腰部以上半身像；头冠、头发、双手与唯一人物道具完整；主体约占画布高度 84%–92%；腰/胯上缘以下衣袍必须在画布底边形成宽幅连续的平直截断，不留透明缝；顶部和左右保留安全边距；不做圆弧/椭圆/徽章/悬浮/渐隐收口；不出现膝盖、脚、蹲跪、盘坐、跨步或全身姿态。** “完整轮廓”只指半身框内的头部、肩臂、双手和唯一人物道具完整，不要求把整个人画全。

第一次生成前按 [references/transparency-workflow.md](references/transparency-workflow.md) 规划透明路径；先做一张校准样片，校准通过后整组固定使用同一路径与参数。

### 4. 逐人生成资产

**先执行 [references/atomicity-contract.md](references/atomicity-contract.md)：每一次调用只能生成一个人物、一个主动作、一个人物道具、一个独立文件。严禁群像、额外道具、拼贴、character sheet、sticker sheet、分镜或海报。**

- 批量生成前，先用阵容中最核心的人物生成 1 张校准样片，立即保存并运行透明通道校验，同时检查画风、取景、比例与 Action Signature。样片通过后才继续生成其余人物，避免把系统性错误复制到整组。
- **每个不同人物必须单独调用一次图片生成。** 一个调用只能得到一个目标角色文件；禁止在同一画布中生成多个角色后再裁切。若主题有 5 个角色，至少执行 5 次独立生成调用。
- 明确要求：**恰好一个人物、恰好一个主动作、恰好一个人物道具**、真实透明背景、PNG、无场景、无文字、无边框、无水印、无签名、无群众、无第二人物、无第二件道具、无重复姿态。若当前工具真实暴露透明参数则必须设置；否则不得虚构参数，改由提示词请求并在落盘后验证。
- 明确要求默认构图为**腰部以上半身角色像**，并把 `waist-up half-body portrait`、`both hands visible`、`lower robe is naturally cropped straight by the bottom canvas edge`、`no rounded or floating lower silhouette`、`no knees, no feet, no crouching, no kneeling, no full body` 同时写入提示词。只写“portrait”或“character cutout”不够。
- 姿态必须来自 Action Signature，不允许默认统一站桩。至少写清一个强主动动词、手与唯一人物道具怎样发生交互、**上身朝向和肩线变化**、视线对象和表情强度。默认不通过腿部动作制造差异；动作必须在半身框内仅凭手臂、肩线、头部角度、视线和这 1 件道具成立。
- 道具必须服务当前动作或提供有依据的身份辨识：例如战略角色可以核阅简牍、验符、按住佩刀或在确有地理动作时操作局部军图；**地图不是军师/将领/三国题材的默认道具**。允许保留史据充分、能显著提高角色辨识的身份器物，即使移除后手势仍勉强成立，但人物必须正在握、佩、阅、按或递交它，不能只在旁边陈列。道具必须保持局部、从属，不得扩张成完整桌案、军帐、战场或信息图背景。
- 历史人物的**唯一人物道具**必须在生成前完成 `Prop Card`：规范名称、角色/事件功能、证据等级、直接来源、来源年代、允许声称范围、图中形制、人物交互、禁加项与置信度。提示词中出现第二件道具、自造复合名词（如“调度筹板”“古代数据板”“流程竹板”）或把多件物品称为“一套”时视为风险信号：不得进入生成。抽象能力（现代系统思维、战略判断、组织能力）不得自动实体化为发明器械。用户指定道具也不豁免史实核验；若其不符合时代，应说明冲突并按用户最终选择处理，不能默默画成史实。
- **地图门槛**：只有当当前 Action Signature 明确需要读取、标注、推演或指认具体地理路线，且移除地图会使动作无法成立时，才允许出现局部地图。不得为了说明‘北伐’自动添加地图、路线箭头、地名、疆域轮廓或战略信息图。地图上避免可读文字与大面积信息化标注。
- **组内核心道具去重**：同一组角色不要人手地图、人手竹简、人手兵器或人手现代设备。若两名及以上角色使用同类核心道具，必须让其物理操作方式、身体重心和叙事功能明显不同；若只是换人继续‘拿/指地图’，至少重设计一人。
- 同组角色若动作剪影相似，优先回到角色功能重新设计动作，而不是仅改朝向。不要制造用户没有要求的戏剧情节。
- 全组保持一致的取景与比例。长兵器、帽冠、披风和手势要留安全边距；除非用户指定，不得让关键部位被画布裁断。
- 对没有可靠肖像依据的历史人物，内部按“基于时代资料的视觉化演绎”处理，不把生成外貌当成真实还原；除非用户追问，不在最终图片回复中追加说明。
- 用户指定保存位置时按其要求保存；否则项目内资产保存到 `output/character-assets/<theme-slug>/`。文件名使用稳定、可排序的 ASCII 名称，例如 `01-zhuge-liang.png`。
- **如果出现多人、群像、拼贴、角色表、多个姿态、场景海报或文字信息图，属于 Atomicity Hard Fail：立即作废，不得基于该错误图继续编辑；从空白重新生成目标单人物。** 只有人物数量与原子构图已经正确时，才允许针对透明边缘、局部道具或裁切做定向编辑。
- **如果用户未明确要求其他取景，而结果出现全身、四分之三身、膝盖/脚、蹲姿、跪姿、盘坐、跨步、依赖地面的姿态，或把衣袍底部做成圆弧/椭圆/徽章/悬浮收口，属于 Framing Hard Fail：立即作废并从空白重生成贴底平直裁切的半身像，不得靠裁切补救。**
- 透明输出采用两级策略：**路径 A 原生 Alpha优先；路径 B 均匀纯色幕布转 Alpha 自动回退。** 如果校准样片缺少 alpha 或把棋盘格画进背景，不反复编辑失败图；从空白重新生成同一人物的纯色幕布草稿，默认使用 `#FF00FF`，再运行 `scripts/chroma_to_alpha.py`。
- 纯色幕布草稿不得出现渐变、纹理、网格、地面、阴影、光晕或环境；人物、服饰、道具和特效不得使用幕布色。顶部和左右保留约 8% 安全边距；默认半身像必须让衣袍在底边形成宽幅连续接触，校验时使用 `--require-bottom-touch`。若结果已有平直宽幅下缘但只差一条透明缝，可运行 `scripts/align_bottom_crop.py` 仅做向下平移；若下缘是圆弧、尖角或接触宽度不足，必须重生成，不得靠脚本伪装修复。主体必须使用品红时，选择与整组配色分离的纯青或纯绿，并全组一致。
- 转换后必须同时通过严格 Alpha 校验和黑/白底视觉预览。校准通过后，整组固定使用同一路径、幕布色、容差、羽化和取景参数，不得混用。纯色幕布校准只允许一次定向重生成；仍失败时停止并保留证据，不把不合格图片标记为最终资产。

### 5. 逐张与整组质检

生成后必须先执行构图与原子性视觉硬检查：**默认腰部以上、贴底平直裁切的半身像；人物数量 = 1；主动作 = 1；人物道具数量 = 1；头冠、肩臂、双手和唯一人物道具完整；无圆弧/悬浮收口；无膝盖/脚/蹲跪/全身；无群像/拼贴/分镜/第二人物/重复人物/场景/文字。** 通过后再检查身份特征、时代/设定、**Action Signature 与 Prop Card 是否真正被画出来**、姿态、服饰道具、画风、取景、比例、透明边缘、裁切，以及是否出现文字、水印或残留背景。逐件核对所有可见道具的证据等级、来源与图中形制；来源说不清、形制不符、应有核心道具被模型漏画、模型擅自增加第二件人物道具，或由多个器物拼造的物件均直接判失败。若人物“换个名字也完全说得通”，视为动作特异性不足，需要重做。

“看起来像透明”的棋盘格不算通过。必须以落盘文件的 alpha 通道与透明像素检查为准。

对已落盘 PNG 运行：

```bash
python3 scripts/validate_character_assets.py output/character-assets/<theme-slug>/*.png
```

纯色幕布回退时运行：

```bash
python3 scripts/chroma_to_alpha.py draft.png final.png \
  --key '#FF00FF' --mode all --allow-bottom-touch --preview-dir qa
python3 scripts/align_bottom_crop.py final.png aligned.png
python3 scripts/validate_character_assets.py --require-bottom-touch aligned.png
```

校验脚本检查 PNG、尺寸、alpha 通道、清晰透明区域、空图风险、四角和边缘接触；转换脚本只处理约定的高色度幕布，不理解人物。黑底与白底预览均无彩边、断裂和雾边，才算通过。视觉判断仍是最终依据。出现明确失败时，用一次只改一个问题的定向重生成/编辑修正，再复查。整组检查按需读取 [references/quality-standard.md](references/quality-standard.md)。

### 6. 只交付最终 PNG

默认交付目录中只放 **5 张最终 RGBA PNG**，使用稳定、可排序的 ASCII 文件名。不要默认创建或交付 `manifest.md`、角色清单、Prop Card 文档、提示词文档、来源文档、QA 预览、原始幕布图或 ZIP。

研究资料、Action Signature、Prop Card、生成参数、Alpha 指标和黑白底预览都是内部工作状态。草稿与 QA 文件应放在任务专用临时目录或非交付工作目录，不得混入最终 PNG 目录；最终图片验证通过后，只把 5 张 RGBA PNG 视为用户资产。

默认最终回复必须只包含 5 个本地图片展示项，每项直接指向一张最终 PNG；不要加标题、人物说明、验证摘要、文件路径列表、下载包、来源链接或结论文字。只有用户明确要求清单、提示词、史据、压缩包、QA 证据或页面接入时，才额外交付对应内容。

只有用户已把页面/项目纳入范围时，才把资产放入页面：沿用现有布局与样式，添加有意义的替代文本，保证响应式尺寸与层级关系，不重写无关部分。没有现成页面时，不为展示效果擅自新建整站。

## 完成标准

任务完成时应满足：

- 仅输入事件主题的调用已经产出并展示 **5 张实际透明 PNG**，没有停在分析、角色方案或提示词阶段，也没有附带用户未要求的文档。
- 未指定数量时默认角色阵容与最终资产数量均为 **5**；只有用户明确要求时才改变数量。
- 每个角色都有通过 8/10 门槛的 Action Signature 和已完成的 Prop Card；每人恰好 1 件有史据、能表达身份或行动的核心道具，动作、手部、视线和道具关系能体现其在当前主题中的具体功能，而不是通用立绘站姿；0 件或 2 件以上均不合格。
- **每张图严格满足一个人物 + 一个主动作 + 一个独立文件**；除非用户明确指定其他取景，均为统一的腰部以上半身像，衣袍在画布底边形成宽幅连续的平直截断且不留透明缝，双手与必要道具完整，不出现圆弧/悬浮收口、蹲跪或全身构图；整组在画风、取景、比例、光线和透明边缘上保持一致，同时人物的上身剪影有清楚差异。
- 每张 PNG 确实包含清晰透明区域，关键轮廓没有意外裁切，且无文字、水印、边框或残留场景；透明性由实际可用的生成路径、Alpha 校验与黑白底预览共同保证。
- 事实、争议、虚构设定和视觉演绎彼此区分。
- 所有项目要使用的文件已保存到项目内，而非只停留在临时或生成目录。
- 默认最终回复只有 5 张 PNG；不输出交付说明。用户明确追问时再提供路径、提示词、生成方式、史据或限制。
