# 总战略库与议题数据关系

总战略数据库（本项目 SQLite）
└─ 议题数据单元（runId）
   ├─ 议题信息
   ├─ 当前世界状态：军队、城池、行动与资源
   ├─ 状态变化记录
   └─ 该议题各战略的结束快照

总战略地图库 `/strategy` 与单独议题 `/discussion?run=…` 共用同一 runId。总库页面是读取、筛选和查看入口，不另外维护一份世界状态，也不推进时间。

- 一个议题单元对应一个实际推演 run。同名议题、同一剧本的不同推演不会互相覆盖。
- 进行中的战略读取该单元当前状态。
- 已完成、未达成、已撤销的战略保留结束时快照，不随后续推演改写。
- 总库列表按议题组织；展开现有“全部策略地图”或检索结果后，可选择议题最新状态，也可选择其下面的具体战略。
- 尚未提供世界数据的议题显示“待初始化”，不会填入伪造的军队或数值。
- 原静态 `public/strategy/library.json` 保留兼容旧素材用途；实时数据以 Agent 数据库为准。

## 只读接口

`GET /strategy-library?limit=100&cursor=…`

返回 `maps`（议题单元目录）与 `nextCursor`。目录中 `id`、`topicId` 都是 runId，`strategies` 是该议题的战略子记录。cursor 使用稳定的议题 ID，分页不会因保存状态导致行号变化而漏项。

`GET /runs/:runId/strategy-map`

返回该议题最新状态。

`GET /runs/:runId/strategy-map?decisionId=…`

进行中战略返回实时数据；结束战略返回历史快照，响应 `historical: true`。对缺少结束记录、无法可靠恢复的旧战略，明确返回错误，不拿今天的状态冒充过去。

网页同源前缀为 `/api/agents`。

## 持久化

- `runs`：议题数据单元。
- `world_states`：当前世界状态。
- `world_events`：逐版本变化记录。
- `world_strategy_snapshots`：归属于 runId 的结束战略快照，唯一键为 `(run_id, decision_id)`。

结束快照与当次世界变化在同一数据库事务中保存。任何一部分失败都会回滚。重复请求不会重复归档。

对于旧版本留下的完整事件记录，启动时按变化前后值恢复历史展示快照；这些快照仅用于查看，不能作为可恢复的模拟存档继续推演。

原界面筛选栏、地图布局、卷轴动画、点击方式和箭头保留，地图显示复用已接入状态数据的组件。
