# 本地世界推演 v1：设计、使用与对接

本版落实已确认的本地规则架构。实现及备份均在“史境Agent-离线素材修复版”内。

## 当前可用范围

- 汉中—长安场景，默认魏延部与长安守军参与推演。地图上其他城市/驻军为静态参考，不自动加入这一战场。
- 行军、急行军、驻守休整、装载补给、派遣运输队、进攻、围困、撤退。
- 人员/粮草守恒、伤员恢复、疲劳、饮水不足、持续缺粮与逃散。
- 运输途中消耗、损耗、会合点交付、截获与返程，禁止物资瞬移。
- 同一时间片双方战力与战损结算；抵达、遭遇、断粮、缺水、疲劳上限、运输抵达、投降、占领时暂停。
- 本地守军根据已获情报守备、补给、撤退或投降；额外配置的军队可在保留守军且补给可达的条件下增援/拦截。
- 本地纯计算、事务存档、幂等请求、版本冲突保护、变化历史与逐时间片计算依据。
- 现有输入框、行动开关、地图点击与详情复用；原卷轴、图片、人物、原箭头函数和全局样式保留。地图固定数字在原位置绑定真实状态。

**这是实验性战役模型，不是已经通过史实校准的历史预测器。**所有系数与默认库存等注明模拟设定。史料用于约束场景解释，未将魏延的十日提案当成实测速度，也未将“负粮五千”当成公斤数。

## 本地使用

运行项目原有启动方式；打开已有北伐议题。在输入框下勾选“下达行动”，每次输入一条：

```text
魏延 行军 长安
推进 1 天
魏延 急行军 长安
魏延 撤退 汉中
魏延 休整
魏延 补给 汉中 10000
魏延 进攻 长安
魏延 围困 长安
推进 6 小时
```

- 记录行动本身不推进时间；用“推进”开始结算。
- 休整需在据点/城外，途中可沿原路撤回；不能把尚未完成的移动改成瞬间回城。
- 补给最后一个数字的单位是公斤粮食当量。现有运力、城市库存及运输队自身口粮不足时拒绝整笔操作。
- 收到重大事件后暂停。再次“推进”表示允许当前命令继续；也可先更换命令。
- 没有勾选行动时不改世界；本地有限语法不冒充自由对话模型。疑问、否定和复合指令不会被猜成行动。
- 文字指令不完整时返回可用语法。已有精确结构化决策可直接走接口。

## 实现文件

- `simulation-types.ts`：模拟状态、命令、运输、情报和计算报告契约。
- `simulation-profile.ts`：版本化参数、代表值/上下界/单位/来源。
- `simulation-state.ts`：初始化与全局人员、资源守恒校验。
- `simulation-engine.ts`：本地命令与时间推进的纯计算函数。
- `simulation-commands.ts`：有限中文指令适配器。
- `world-agent.ts`：唯一持久化写入口，SQLite 事务、幂等与历史记录。
- `world-bootstrap.ts`：符合范围的新议题初始化、旧空白议题兼容。
- `strategy-view.ts`：界面数据投影。

文件路径均相对 `agents/src/`。

## 计算机制

移动速度 = 基础速度 × 地形 × 天气 × 负重 × 疲劳 × 行军方式 × 合格导航效果 × 道路容量分配 × 口粮条件。

食物需求 =（可战人员 + 伤员 + 运输人员）× 每人每日口粮 × 时间。

有效战力 = 实际接战人数 × 训练 × 装备 × 士气 × 疲劳 × 口粮 × 城防条件。

每方暂失战力人数 = 该方接战人数 × 交战损失率 × 时间 × 有上下限的敌我战力比。

双方损失先基于同一快照计算再同时应用。接战容量在多个对手之间分配；少于一人的损失保留小数余量，避免小时间片舍入为永远不损兵。人员按伤员、阵亡、被俘、逃散分类。转为伤员不会被再次计为阵亡；休养恢复从伤员转回可战人员。

城内粮仓与军队携粮为两个账户，需明确调拨；居民与可用运输人员也消耗粮食。城市占领只改变实际控制，不产生额外库存。

内部最多按一小时切片，在抵达、道路相遇、口粮/饮水耗尽、效果到期、疲劳上限等更早边界缩短时间片。前端按推演日展示，存档保留实际经过小时。

本地规则使用存档中锁定的参数副本，默认使用代表值，不每次随机抽上下限。当前没有额外随机胜負骰子，因此相同输入可复现。今后添加随机事件时必须增加可回放的种子/抽样记录及相应测试。

## 接口

网页同源前缀：`/api/agents`。本机后台默认 `http://127.0.0.1:4318`。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/runs/:id/world` | 完整世界快照与来源，管理/展示使用 |
| GET | `/runs/:id/world-observation?faction=shu` | 给角色 Agent 的己方状态与已获情报 |
| POST | `/runs/:id/world-order` | 提交行动，不直接提交数值变化 |
| POST | `/runs/:id/world-advance` | 本地推进时间 |
| GET | `/runs/:id/world-events?afterRevision=0&limit=50` | 分页增量事件，供 UI/队友消费 |
| POST | `/runs/:id/messages` | 现有聊天输入适配 |

例：

```json
{
  "commandId": "unique-order-001",
  "expectedRevision": 0,
  "armyId": "army-wei-yan",
  "kind": "march",
  "targetCityId": "changan"
}
```

推进：

```json
{
  "commandId": "unique-advance-001",
  "expectedRevision": 1,
  "hours": 24
}
```

`kind` 支持 `march / forced-march / garrison / resupply / attack / besiege / retreat`。
补给使用 `sourceCityId`、可选 `foodKg`；不传 `targetCityId`。

响应 `worldResult` 包含实际版本和是否重复请求，同时返回最新页面投影。事件 `simulationReport` 保存规则版本、实际推进时间、暂停原因、计算输入和结果。

**请求规则：**同一请求重试必须保留 commandId 和原始内容；相同 ID 不同内容、过期 expectedRevision 均拒绝。传入 `troops` 等额外字段拒绝。GET 不推进时间。

### 队友系数

首版只开放一种明确注册的导航效果，不开放任意参数写入：

```json
{
  "id": "route-familiarity",
  "factor": 1.05,
  "roadId": "road-ziwu",
  "durationHours": 12,
  "reason": "已登记部队熟悉此路段"
}
```

放在 `world-order` 的 `effects` 数组。引擎检查军队 `knownRoads`，仅描述“熟悉”不能凭空获得能力；同组不能叠加、不能刷新延长现有效果、到期清除。新增效果种类需先定义依据、范围、有效期、互斥关系，再添加规则。

角色决策应使用 `world-observation`，不能把全量世界快照当成角色已知情报。当前同势力共享已观察情报，未模拟信使通信延迟。

### 裁判与 API 边界

本地对局拒绝通过原 `world-events` 接口直接改数字，避免两个裁判同时记账。已绑定外部引擎的局也不能混用本地结算。模式切换和外部数据校正尚无自动接口；需要明确迁移。

世界推演模块没有任何外部网络请求。项目其他模块原有的选角、生图 API 设置继续由各自模块控制；本地行动和推进不会触发生图队列。

## 已知模型边界

1. 240 公里路线、道路容量、库存、居民人口以及战损率等均为模拟参数，尚未做历史地理核定与独立历史案例校准。
2. 默认只配置一条战役道路、两支参与军队。其他地图据点不自动模拟全国政治、经济和外交。
3. 补给会合点在出发时固定，收货部队离开时运输队等待；暂未提供运输队改道命令。不能把这种等待误认为物资已交付。
4. 饮水采用可达水源/携水模型；不包含水源流量、疾病医学、畜力和车辆类型细分。
5. 围困为单通道战役抽象；多出入口城市、海运封锁需要扩展通道模型。投降阈值与攻城系数仍是游戏规则。
6. 未实现自由语言离线大模型、主动侦察任务、信使延迟、地形动态破坏或全国补员系统。
7. 参数的敏感性与历史合理性不能仅由软件测试保证，需继续用独立案例校准。

## 验证与回退

运行：

```text
npm run agents:build
node --test agents/tests/local-simulation.test.mjs agents/tests/world-state.test.mjs
npm run build
```

新测试数据库建在 `agents/tests/.runtime` 下并在结束后清理。验证包含初始化、跨回合重复请求、同时结算、断粮/缺水、急行军阈值、运输返程、围城、存档恢复和角色情报隔离。

原有素材库测试存在固定数量假设：要求 30 张而目录实际 31 张。本次不删除素材，也不改队友测试来掩盖此失败。

修改前备份位于项目内 `.world-state-recovery/local-simulation-20260913-024806/`，含原文件哈希和数据库快照 `agents-before.sqlite`。恢复数据库前必须停止本项目服务，避免覆盖用户后续对局进度。
