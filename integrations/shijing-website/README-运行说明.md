# 史境 · 主页、议题讨论与自动生图整合版

## 目前完成的流程

打开主页的战略地图，点击“发起新议题”，填写议题、背景、年份和阵营，再点击“创建并进入讨论”。也可以点击首页的最新议题，或从事件详情点击“进入议题讨论”。讨论页保留原卷轴布局，标题、五名人物、身份、开场对白和建议会跟随议题变化。

后端先研究选角与道具来源，再生成五张独立人物 PNG 和一张故事板。人物卡片、对话头像与当前人物大图共享同一人物资产。故事板根据讨论的新主题或事件阶段更新；同题一般追问保持原画面。每张图经过像素检查或模型视觉检查后才显示。失败保留已通过的结果，可重试未完成项。较慢的旧轮次不会覆盖新轮次。

**真实生成尚未验收：需要配置用户自己的服务。当前没有有效 API 密钥，因此未进行真实选角、生图或视觉验收。已通过的接口测试使用模拟响应，不能作为生成质量证明。** 未配置时页面明确显示“尚未连接生成服务，本次图片未生成”，不会用子午谷旧图代替新议题成果。

## 本地运行

需要 Node.js 22.13 或更新版本。

```sh
npm ci
cp .env.example .env
# 在本机编辑 .env，填入已有服务配置
npm run dev
```

打开终端显示的本地网址，默认是 http://localhost:3000/ 。

- `/`：战略地图主页。
- `/discussion?topic=...`：带议题内容的讨论页；主页自动产生这个链接。
- `/api/topic`：GET 查看是否已配置；POST 研究当前议题与五人选角。
- `/api/characters`：单个人物 PNG 生成。
- `/api/storyboard`：单张当前故事场景生成。
- `/api/validate-image`：图片视觉与总结文字检查。
- `/api/chat`：当前人物对话与场景变化判断。

## 服务配置

在服务端 `.env` 中配置，不要放在网页前端或提交密钥。

| 配置 | 用途 |
| --- | --- |
| OPENAI_API_KEY | 用户自己的服务密钥 |
| OPENAI_BASE_URL | API 根地址，默认 https://api.openai.com/v1 |
| OPENAI_CHAT_MODEL | 选角、对话与图片验收模型，默认 gpt-5.6-luna |
| OPENAI_IMAGE_MODEL | 生图模型，默认 gpt-image-2 |
| OPENAI_WEB_SEARCH | 默认 true，选角阶段检索史据 |
| NEXT_PUBLIC_SITE_URL | 对外站点地址，仅用于站点元信息 |

兼容服务需支持 Responses API、JSON Schema、图像输入、web_search、Images generations/edits、透明 PNG 及对应尺寸。若服务缺少某项能力，需要按实际接口适配，不能只填密钥就宣称完成。关闭检索会降低史据核验能力；不推荐在历史选角中关闭。配置后重启本地服务，再点击“重试未完成项”。每次真实生成与视觉验收会使用所配置服务的额度。

## 两份 skill 的接入

`skills/storyboard-character-assets` 保存用户提供的 v6.3.1 参考包；`skills/conversation-storyboard` 保存用户提供的 v5 参考包。附件作为需求与美术规则来源，网页不会执行其中任意命令，也不会通过前端调用 Codex 的内部生图工具。

`scripts/sync-skill-rules.py` 将选角、动作、史据、原子性、话题路由及故事画面规范转换成后端可导入规则，保留原文件便于后续更新。

- 人物：每张一个人物、一个主动作、一个有来源的核心道具；腰上半身，贴底平直裁切。先尝试原生透明；首张透明检查失败才重新生成纯品红幕布并转换 Alpha，校准成功后全组锁定该路径。不能将全身图强行裁成半身。校准未通过时停止后续人物生成。
- 故事板：一张连续竖幅场景，含左侧总结短文；日间黑字、夜间白字，无文字底板。接口输出 912×1616，经约 1.7% 的居中边缘裁切得到 **904×1602（精确 452:801）**；没有拉伸。比例偏差过大直接拒绝。
- 验收：浏览器检查 Alpha、透明边界、可见主体和贴底接触，并创建黑白底预览供视觉模型检查；故事板在裁切后核对主题、阶段与文字。模型验收不能保证绝对无误，真实产出仍需使用者检查。

已成功的图片和选角保存在当前浏览器的 IndexedDB，便于刷新和重进同题时复用；不是跨设备云端资产库。主页议题记录保存在当前标签页会话。存储不可用会提示只保留当前页面。重新进入讨论页会恢复图片，聊天记录不持久化。
