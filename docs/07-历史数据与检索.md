# 07 · 历史数据与检索（facts / RAG）

> 产物：`packages/facts/`（含 `facts-db`、`searcher`、`estimator`）。
> 依赖 06(llm/embed) 与 11(safeFetch)；被 01(填充) 调用。

## 1. 目标

给"话题 → 模拟世界"供给**可信底座**：

```
话题链接 → 正文解析(01)
   ├─ 命中事实库 → direct
   ├─ 检索补充（搜索 API/二次抓取）→ Fact{source:search}
   └─ 真的缺失 → AI 估算（estimated + confidence）→ 可复核
```
**规则：宁缺毋滥、估算必标注。** Fact 会进 `Spec.factsUsed`，界面同理可溯源。

## 2. 数据模型

```ts
type Fact = {
  id: string; entity: string; claim: string;
  source: 'top' | 'search' | 'rag' | 'ai';
  url?: string;            // 出处
  value?: number | string;  // 可数化则带数值
  unit?: string;
  estimated?: boolean;      // 估算项
  confidence: number;       // 0..1（估算填，检索按命中分）
  tags: string[];           // 朝代/人物/经济/军事…
  embedded: number[];       // 提供给 (RAG) 向量
};
```
存储：SQLite `facts` 表（结构化）+ 向量在 Chroma（或内存 idx，MVP 可只 BM25）。

## 3. 检索层（Searcher）

实现：`searcher.ts`（BM25 + 可选向量混合，`score = 0.7·sparse + 0.3·dense`，max 归一，`confidence ≥ 0.6` 才出示）。

接口：

```ts
search(q: string, opts: { limit?; minConfidence?; queryVector? }): SearchHit[] // { fact, score }
// 策略链：tokenize → BM25（文档 = entity + claim + tags）→ 阈值/度量标化 → 降序切片
```

抗跨域污染的四道闸（按序）：

1. **查询分词丢弃单字 CJK**：`tokenize(query)` 仅保留 ASCII/数字 token 与 ≥2 字 CJK 词组——单字「战/乱/欧」会把整库都带进来（正是早前「北伐」话题混入北宋司马光的根因）。
2. **`MIN_SCORE = 0.03` 最小相关性门**：归一化 BM25 分低于此值视为纯词频噪声（如「爆发」二字把二战文档带到一战话题），直接丢弃。
3. **精确命中优先**（topic-pipeline 断言）：查询命中实体/标签本身（`entity.includes(q) || q.includes(entity) || tags.includes(q)`）时不再退回收宽匹配——同一查询「司马懿」不会把「司马光」带进 pool。
4. **语义亲和门**（topic-pipeline `topicAffinity`）：无精确命中时，仅采纳与话题有语义重合的 Fact——`claim` 与话题正文 ≥2 个共现词组，或任一 `tags` 与话题检索词有包含关系。跨题材实体靠单个泛词（如「爆发」）的漏网命中在此被拦截。

另：同分池内**人名实体优先**（`isPersonName`，见 01 §4 构演司）——希特勒类真名排在「德军/诺曼底」之前入池，保证人物 cast 能凑齐二人。

## 4. 外部搜索降级链（按优先级）

1. **本地/缓存**（facts 表 + 文件：如 `_refs` 与 D盘剧本）——快且免费
2. **内置百科快照**（预置常用历史条目 json，whitelist）——成本可控
3. **在线搜索**（Tavily/Bing 等，都走 safeFetch + 限流）——**未配置 key 时直接回退 4**
4. **AI 估算**——`Estimator`：给 LLM 已知事实 + 问题，输出 `{value, reasoning}`，`confidence` 由模型给或固定 0.4

> 注：第 3 层需要外部搜索 key，环境变量 `SEARCH_API_KEY`；没有就自动跳过（不会中断管线）。

## 5. Estimator（估算器）

- 由 `llm.generate`（tier=cheap）做；输出 JSON `{value, unit?, lower?, upper?, basis}`。
- 校验：`lower ≤ value ≤ upper`，值与话题相关（0/1 BinClassifier 可复用 01 的 Validator）；不过 → 拒收，标记为"未知"（不硬填）。
- **返回 Spec 时，估算项以 `estimatedRate` 汇总显示给玩家**（见 01 号 §6）。
- **数值的溯源链随 spec 出库**（见 01 §4 数值司）：数值司动态产出 `provenance[]`（每个指标：source=数据出处、how=检索/换算路径、estimate=无直接记录时的估算假设链）与 `derivations[]`（每条规则：formula=落地公式、why=为什么这样推、ref=依据的事实/惯例）。即「数值从哪找真实、公式怎么推」两条链由 AI 动态生成并交 UI 展示（离线 mock 亦产出确定性版本）。

## 6. RAG 组装（供 04 记忆 query）

```
search(q, k): embed(q) → top-k by cosine → 段长 ≤ 200 char → 拼 context 块
```
- chunking：按句群滑窗（重叠 50），来源不变
- 更新：新 Fact 插入即嵌入；全文重索引可后台（`npm run facts:reindex`）
