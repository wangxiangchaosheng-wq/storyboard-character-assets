# 03 · 裁判系统（Referee）—— 裁决协议与双引擎

> 位置：`packages/engine-core/referee/`；被 `engine-core`(02) 在每回合 point 4 调用。
> 参考：whodunit 的"裁判/可见性"与 deepwolf 的"裁判校验玩家动作"模式（`_refs/whodunit`、`_refs/deepwolf`）。

## 1. 目标

把「数值合法性」与「叙事合理性」分离成两层裁决，任何玩家动作/剧情节拍都必须过裁判；**角色（Agent）永远不能自判**。

## 2. 双引擎结构

```
                 ┌───────────── 裁决入口 adjudge(case) ─────────────┐
                 ▼                                                │
  A. 确定规则器（Deterministic）        B. LLM 裁判（JudgingAgent）──────┘
     · rules 全量本地计算                · 仅处理"表意性"（计谋/识破/叙事）
     · 越界 clamp                        · 输入=脱敏案例包（无未来信息）
     · 输出 deltas（固定形状）            · 权重限幅：|delta| ≤ maxRuleDelta
```
每次裁决结果 = A 与 B 的**并集交集规则**：
- A 出的 deltas 恒生效；
- B 出的 deltas 需要符合 `clamp` 与上下界，如与 A 冲突以 A 为准（确定性优先）；
- B 结果记录到 `Settlement.reasons` 供叙事。

## 3. 数据契约（类型源：`shared/contracts/referee.ts`）

```ts
type AdjudicationCase = {
  turn: number;
  actor: string; action: { kind: string; text: string };
  statePack: { metrics: Record<string, number>; attitudes: Record<string, number>; world: { events: string[] } };
};

type Settlement = {           // ← 中间产物，也是 02 的携行件
  deltas: Delta[];            // 形 {metric, delta, why}
  status: 'ok'|'pending'|'rejected';
  reasons: { actor:string; text:string }[];     // 对玩家的原因（public）
  hidden: string;             // 对裁判直说（private，防泄）
  mapChanges: { expr; value }[];
  longTerm: { key; value }[];  // 被记忆系统固化（04）
};

type RuleDb = { ruleId: string; expr: string; clamp: [number,number]; runtime_ms: number }[];
```

## 4. 裁决协议

1. `engine` 提交 `case`（不含未来信息；LLM 裁判**无**事件预览）。
2. 确定性引擎先跑规则 → `baseDeltas`。
3. LLM 裁判只输出「非确定性 decide」的增量，**禁止改 baseDeltas 的结构性**；必须给 `reason`。
4. 合并 → 应用 clamp → 返回 `SettlementResult`。
5. 全程 append 到 `eventLog`（02），`publicNarrative` 与 `hidden` 分道。

## 5. 对抗性/公平性点

- LLM 裁判本身也要"出庭"：它的裁决若明显与事实相反（如玩家抢先成功），`checker` 阶段做一次确定性复核（写 02 里），不符 → 走 `pending` 事件让玩家重新申诉？**MVP 不做申诉**，只做警告并差额补偿。
- 输入提示词规范（见 06 号 §prompt）：必须把"角色视角 vs 客观真相"分开；泄露未到期的隐藏信息 = 系统级错误（04 号 LeakDetector）→ 触发回滚重裁一次。

## 6. 裁判组件开发拆解

| 任务 | 内容 | 验收 |
|---|---|---|
| R1 | 确定性引擎（纯 TS，canonical rules）翻 02 的 rules | baseDeltas 全量断言 |
| R2 | case pack 构造 + LLM 裁判 prompt（重点：无泄漏、reason 必填） | 试跑 20 案例无泄漏事件 |
| R3 | 合并器 + clamp + 冲突规则 | 冲突单测：定优先、llm 越界 clamp |
| R4 | 写日志 & 权限钩子（防 Agent 自判） | 引擎直判测试被拒 |
| R5 | checker 复核 + 补偿 | 反事实案补偿通过 |

## 7. 验收清单

- [ ] 确定性裁决与 LLM 裁决可分别单测；合并无冲突用例
- [ ] `hidden` 字段绝不进入 `playerView`（04 验证）
- [ ] 任何非法 action（引用未来/不存在 metric）→ `rejected` 且带原因
- [ ] 同一 case 重跑确定性 ≥2 结果一致（LLM 部分不参与确定性断言）
