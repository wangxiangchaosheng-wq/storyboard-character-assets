## 1. 分工与工作流（防"等图卡壳"）

```
引擎/前端（我们）：只调 useAsset('portrait/wei-yan') 这类 key
美术/视觉(队友)：写 apps/web/assets/manifest.json + 放文件
合并：pnpm assets:check 全绿（manifest 的 key 与代码引用的 key 一致）
视觉没交付前：运行时自动回退占位 SVG（名字+类别+按 key 着色的确定性图形），绝不破布局
```
- 代码引用的 key 必须登记进 manifest；`assets:check` = ①manifest JSON 可解析 ②每个被引用的 key 有 entry ③file 存在（可以存在占位 png 也行：占位文件放 `assets/.gen/**`，由 `pnpm assets:gen-placeholders` 生成）。
- **美术同学交付新图 = 改 manifest + 放文件 + 跑一遍 check**；不需要动任何 TSX。

## 4. 运行时接口（前端所依赖的唯一口）

```
useAsset(key) -> { url, isPlaceholder }
getAsset(key, 'image'|'audio')       // 非 React 环境（Electron/CLI）同
assets:gen-placeholders               // 生成占位 SVG（按 key 色块+名称）
assets:check                          // 覆盖校验（CI 门）
```
- 占位策略：`placeholder/{colorFromKey}/{name}`；`isPlaceholder=true` 时 UI 显示 3px 虚线框 + key 名 + "待交付"角标，**即使全部素材没做，游戏流程照跑**。
- 图片优化：`<img>` → `decoding=async` + `fetchPriority` 按使用场景；立绘 2× （`@2x` 变体）由 manifest `variantOf` 表达。

## 5. cpk-agnes 生图衔接（06）

- 立绘/事件图可用 06 的 `ImageProvider` 异步生成草稿（关键词：历史载象风 + 白描/水墨风格 prompt 模板，见 06 §6），结果写回 `assets/output/**` 与 manifest，再人工精修。
- 美术同学拿到生图草稿后直接替换 `file` 路径即可，接口无感。
