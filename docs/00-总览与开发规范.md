# 00 · 总览与开发规范（模块文档根索引）

> 本文档是整个项目的**导航 + 章程**：先读它，再按模块分工开发。
> 对应原始总纲：《后端架构方案.md》（v4 摘要，本文是其细化拆分）。

---

## 1. 项目一句话

任何知乎话题（或自拟问题）→ 安全抓取/检索 → AI 多轮生成（数值公式 + 世界观剧本 + 角色设定）→ 校验对齐 → 玩家选角 → 投入通用推演引擎 → 桌面(Steam) / 网页 / 小程序 / 安卓 / iOS 都能玩。

**北伐只是第一个剧本实例**；引擎与话题无关（只认 `ScenarioSpec`）。

## 2. 关键约定（全项目强制）

| 约定 | 内容 |
|---|---|
| 语言 | 全 TypeScript，strict 模式；**不使用 Python/FastAPI** |
| 确定性 | 所有数值结算**必须是确定性函数**（同输入同输出，可单测断言）；LLM 只用于：反应/叙事/裁判裁决、生成与校验 |
| 单一事实源 | 每一局的世界真相 = `eventLog`（事件日志），其余视图（角色视图/UI）都由它投影生成 |
| 存取分离 | 引擎 core 不依赖 DOM/Electron/网络；所有 IO 由外层注入 |
| 契约 | 模块间类型以 `shared/contracts/*.ts` 为唯一真源，文档内类型仅为阅读复制件，修改代码前先改契约 |
| 安全 | 服务端请求 URL：仅允许 http/https；发请求前校验 host，拒绝 localhost、环回、私有与保留地址（所有出站请求必须过 `safeFetch`，见 11 号） |
| 密钥 | `.env` 注入（含 cpk-agnes key），**严禁 commit**；`.env.example` 全量枚举 |

## 5. 编码与协作规范

### 5.1 语言与代码风格
- `strict: true`；禁止 `any`（必须 `unknown` + 收窄）；公开函数全部显式返回类型。
- 文件命名：kebab-case；类型文件 `typings.ts`，schema 文件 `schema.ts`。
- 每模块一个 `index.ts` 只导出公开面，模块间**禁止互相 import 路径穿越仓库边界**（跨模块用 `@engine/**` alias 且只在 package 条接口）。
- 错误：统一 `AppError {code, message, details?, cause?}`；**错误码全局唯一**（见 05 号附录）。

### 5.2 Git 规范
- 分支：`feat/engine-memory`、`fix/ssr-safe-url` 等 `<type>/<mod>-<desc>`。
- commit：Conventional Commits，正文一句话说明+验收项；一个 PR 一个模块、≤400 行 diff（评审友好）。
- 代码先过 `check`+`lint` 再 push。

### 5.3 测试门槛（合并前强制）
- 引擎数值快照、隔离泄密用例、safeFetch 拒绝用例 → **必测且必须 PASS**；
- 其余以模块内 `验收清单` 为准；覆盖率低允许，但禁用 `skip` 掩盖。

## 6. 环境变量（全列）

见 `.env.example` 模板：`AGNES_BASE_URL/AGNES_API_KEY/AGNES_CHAT_MODEL/AGNES_IMAGE_MODEL/RAG_*`、`SQLITE_PATH`、`SSE_HEARTBEAT_MS`、`LLM_CONCURRENCY`、`LOG_LEVEL`。缺失时服务以 logging 警告启动（agent.mock 模式），**不得硬编码默认 key**。

## 7. 里程碑速查（详见 10 号）

P0 引擎单机可跑（5-8回合）→ P1 话题管线首用例 → P2 服务器+SSE + SQLite → P3 SPA 可玩 → P4 四端壳 → P5 打磨验收。
